Developer Implementation Requirements
Purpose: Add the following AI-powered lead qualification, intent detection, dashboard, and human-review capabilities to the RichLead SaaS product. These requirements are intended to be implementation-ready for the development team.

3. Buying / Intent Signals
The AI should detect relevant public/company-level signals that may indicate a reason to contact a prospect. Signals should be stored against the lead/company and surfaced in the lead profile and review workflow.

Example signal:

Implementation note: Do not invent signals. Each detected signal should include its source/reference and detection date where the underlying data provider makes that information available.

5. Review Queue – Recommended UI Behavior
Show lead identity and company information at the top of each review card.
Show ICP score and priority clearly.
Show detected buying/intent signals.
Show a concise AI research summary.
Show the generated subject line and message body.
Allow inline editing before approval.
Regenerate should create a new message while preserving the lead and campaign context.
Reject should remove the message from the active send queue and record the rejection status.
Approve should move the message to the campaign/send queue.
Bulk approval should only apply to messages selected by the user.
Record reviewer, timestamp, action, and message version for audit/history.

7. End-to-End Processing Flow
1. Apollo / Lead Source → Lead Discovery
2. Lead → AI Qualification
3. AI Qualification → ICP Score
4. Lead / Company Data → AI Research
5. Research + Intent Signals → Personalization Context
6. Personalization Context → AI Message Generation
7. Generated Message → Review Queue
8. Human Review → Approve / Edit / Reject / Regenerate
9. Approved Message → Campaign / Sequence
10. Campaign → Send
11. Replies / Outcomes → Analytics + AI Recommendations

9. MVP Acceptance Criteria
Every imported/discovered lead can receive an AI ICP score.
The score includes an explainable breakdown.
The system can display supported buying/intent signals without fabricating data.
AI research is visible from the lead/review experience.
AI-generated messages enter the Review Queue.
User can Approve, Edit, Reject, or Regenerate an individual message.
User can bulk-select messages and use Approve Selected.
Approved messages can be passed to the campaign/send workflow.
Dashboard counters update from actual stored data/events.
Review actions and message versions are persisted for audit/history.
10. Developer Notes
Keep the architecture modular so the AI layer, Apollo/data integrations, email sending, campaign engine, and UI can evolve independently. Intent signals that require external data sources should be implemented only when the relevant source/API is connected. For the MVP, prioritize the AI scoring → research → personalization → human review flow.
